# 记账本 · 数据模型与迁移方案

> 版本 v1.6.0 · 面向「从一飞记账迁出、此后只用本 App」的场景

---

## 一、为什么要重新设计

一飞记账已停止运营。旧账的价值不在于还能不能再打开它，而在于**历史数据能否成为新系统的可靠起点**。
因此这次不是"把 xlsx 读进数据库"，而是**一次性完成数据模型切换**。

旧方案有几个会让账本身出错的点：

| 问题 | 具体表现 | 财务后果 |
|---|---|---|
| 没有期初余额 | 余额 = 全部账单从 0 累加 | 算出来的是"净流水"，不是账户真实余额，永远对不上 |
| 退款/报销未冲减 | 统计直接 `sum(amount)` | 支出虚高、结余率虚低 |
| 手续费不入支出 | 单独列"手续费"但不计入支出合计 | 账户减少 ≠ 支出合计，月末有缺口 |
| 重复导入无去重 | 同一文件导两次 | 金额直接翻倍 |
| 净资产口径混合 | 公积金/医保/投资与活期一起加 | "看着有钱，其实动不了" |

---

## 二、核心不变式（整个系统的地基）

```
账户余额 = 期初余额 + Σ 账单流水影响 + Σ 对账调整
```

- **账单流水影响**：支出 −金额；收入 +金额；转账 转出 −(金额+手续费)、转入 +金额
- **对账调整**：账单解释不了的余额变化（手工改余额、借款还清等），必须带金额落库
- **期初余额**：开始记账那一刻账户里已有的钱。由「真实余额 − 流水 − 调整」反推得出

代码实现：`data/BalanceEngine.kt`（唯一入口）、`data/Reconcile.kt`（写调整流水）

## 三、数据模型

### Asset（账户）

| 字段 | 说明 |
|---|---|
| name / subType / icon | 名称、类型、图标 |
| type | 0 普通账户 / 1 信贷账户 |
| amount | 当前余额（缓存值，由引擎重算） |
| **openingBalance** | **期初余额（新增）** |
| **openingDate** | 期初日期（新增） |
| totalQuota / chargeOffDate / repaymentDate | 信贷额度、出账日、还款日 |
| inTotalAsset | 是否计入净资产 |

### Category（分类）

| 字段 | 说明 |
|---|---|
| name / type / icon | 基础信息 |
| **parentId** | **上级分类（新增）**，支持「食 → 正餐/外卖/咖啡」 |
| **nature** | **支出性质（新增）**：1 固定 / 2 弹性 / 3 不计收支 |
| hide | 大类节点设为 true，不出现在记账网格 |

> 大类节点用 `hide = true`，因此不会污染记账页的分类选择，只服务于报表归集。

### Bill（账单）

| 字段 | 说明 |
|---|---|
| type | 0 支出 / 1 收入 / 2 转账 |
| amount / refundAmount / reimburseAmount | 金额、退款、已报销 |
| serviceCharge / discount | 转账手续费、优惠 |
| assetId / fromAssetId / toAssetId | 账户 |
| recordType | 0 手动 / 1 导入 |

### Adjust（对账流水）

| 字段 | 说明 |
|---|---|
| amount | 调整额（正加负减），账单引起的动作记 0 作为备忘 |
| kind | 1 余额调整 / 2 账单删除冲正 / 3 账单修改冲正 / 4 借款冲销 / 5 借款删除 / 6 账户信息变更 / 7 账单恢复 |
| balanceAfter | 调整后余额快照 |

### Loan（借入借出）

含 `repaidAmount` 与 `imported` 标记。还款按「同人优先 + 时间最早」FIFO 冲销，`outstanding = amount − repaidAmount`。

### Budget（预算，新增）

`categoryId` 为空表示账本总预算；`month` 为空表示每月循环。

## 四、导入迁移向导（四步）

入口：设置 → 导入迁移向导。原「账单导入」保留为快速导入。

### 第 1 步 · 体检报告
只读预扫描（`excel/ImportScanner.kt`），输出：账单笔数、时间跨度、覆盖天数、账本、账户数与**每个账户的流水累计**、分类笔数与金额、支出/收入合计、异常行数。

### 第 2 步 · 账户认领（最关键）
每个账户填一次"今天的真实余额"（对着银行 App 看一眼）。系统按

```
期初余额 = 真实余额 − 流水累计 − 对账调整
```

反推期初并写回。这一步做完，账从此永远是平的。

> 若填写的值与流水累计相同，说明记录很完整，期初为 0；
> 差额较大通常意味着有未记录的支出或开户时就有的余额。

### 第 3 步 · 分类重构
逐条给支出分类标 **固定 / 弹性 / 不计收支**，并可归入大类（食/住/行/购物/娱乐/医疗教育/人情/金融/其他）。
- 固定支出：房租、房贷、物业、水电、话费、订阅、保险等，用于计算"真实可压缩空间"
- 不计收支：还款、借贷、内部划转，避免与账单重复计算

### 第 4 步 · 执行与稽核
写入后逐账户输出：

```
期初 ¥A ＋ 流水 ¥B ＝ 期末 ¥C
```

差异必须为 0。同时报告跳过的重复账单与异常行。

## 五、报表口径（全 App 统一，见 `data/Finance.kt`）

| 指标 | 公式 |
|---|---|
| 支出 | Σ(金额 − 退款 − 已报销) + Σ 转账手续费 |
| 收入 | Σ 收入金额 |
| 结余 | 收入 − 支出 |
| 结余率 | 结余 ÷ 收入 |
| 可支配资产 | 非投资类账户正余额之和 |
| 投资资产 | 投资理财类账户正余额之和 |
| 应收借出 | Σ 借出未还净额（`amount − repaidAmount`），属资产 |
| 负债 | 负余额账户绝对值之和 + Σ 借入未还净额 |
| 净资产 | 可支配 + 投资 + 应收借出 − 负债 |
| 总借入/总借出 | Σ 未还净额（已还部分已冲销），与净资产口径同源 |

> 借出不计入净资产是错的：借出时账户余额已减少，若不把应收加回，净资产会凭空缩水；还款时又凭空回涨。同理借入必须在负债里体现，否则借钱当天净资产反而变大。

## 六、导出 / 导入一致性

导出的 xlsx 含五个 sheet：**支出 / 收入 / 转账**（兼容一飞格式）＋ **账户 / 对账**（本 App 扩展）。

- 「账户」含当前余额与**期初余额**，导入时先按流水重建，再用它校准
- 「对账」回放调整流水并去重（同账本 + 同账户 + 同时间 + 同金额视为同一条）

因此 **导出 → 清库 → 导入，余额严格一致**。旧版文件（只有三个 sheet）仍可正常导入。

导入去重指纹：`类型 + 时间 + 金额(分) + 账户 + 备注`。

## 七、本轮未做，建议下一步

1. **标签 / 项目维度**：旅行、装修这类跨分类支出，需要第二维度才能正确归集
2. **周期账单**：房租、订阅、还款自动生成，防漏记，同时为「固定支出」提供数据源
3. **商户字段**：支持"某店一年花了多少"与输入自动补全
4. **多币种**：若有外币账户，需要汇率与折算口径
5. **两级分类在记账页的展开选择**：目前大类只服务报表，记账页仍是扁平网格
